# 迭代计划

本页说明凡语言各仓库的分工关系，以及后续的演进方向。

## 一、仓库分工关系

凡语言由多个仓库协同构成，每个仓库承担明确且单一的职责：

| 仓库 | 职责 | 说明 |
| --- | --- | --- |
| [`fan-rust`](https://github.com/china-lang-fan/fan-rust) | 全套实现 | 凡语言的主要实现，规划涵盖运行、编译、打包的完整命令链：词法分析、语法分析、树遍历解释、字节码、虚拟机（VM）、语言服务器（LSP）。 |
| [`fan-go`](https://github.com/china-lang-fan/fan-go) 及未来的 `fan-*` | 多语言宿主 | 供其他编程语言解释执行或内嵌凡语言脚本的实现，只做解释执行（树遍历），不实现 VM 与编译。语法与语义以 `fan-rust` 为准，各宿主实现保持对齐。 |
| [`fan-sdk`](https://github.com/china-lang-fan/fan-sdk) | 开发库 | 凡语言的共享标准库，包含全部基础类库与扩展类库；后续会通过目录进行分类组织。各宿主实现共用同一份 SDK。 |
| `fan-*-plugin` | 编辑器插件 | 凡语言在各类 IDE / 编辑器中的插件，例如 VS Code 插件 `fan-code-plugin`、JetBrains 插件 `fan-jetbrains-plugin`、Zed 插件 `fan-zed-plugin`。 |
| [`china-lang-fan.github.io`](https://github.com/china-lang-fan/china-lang-fan.github.io) | 官方文档 | 凡语言官方说明文档站点，包含使用指南、标准库文档、示例与语法参考。 |

### 协作约定

1. **以 `fan-rust` 为语义基准**：新的语法特性与运行时行为优先在 `fan-rust` 落地，`fan-go` 等宿主实现随后跟进对齐。
2. **共享 SDK 是双端契约**：所有宿主实现加载同一份 `fan-sdk`。SDK 中的原生绑定通过 `本地("模块.函数名")` 的命名空间形式声明（例如 `本地("regex.regexMatch")`、`本地("json.jsonEncode")`、`本地("http.httpRequest")`），各宿主按此名称注册原生函数；原生实现缺失时静默回退到函数体。
3. **插件与文档独立演进**：编辑器插件只负责编辑体验（高亮、补全、LSP 接入等），不内置语言实现；文档随特性迭代同步更新。

## 二、执行方式与命令体系

`fan-rust` 是全套实现，提供从运行到分发的完整命令链；其他宿主实现只做解释执行。

| 命令 | 输入 → 产物 | 执行方式 | 状态 |
| --- | --- | --- | --- |
| `fan run` | 源码 `.凡` | 树遍历解释执行 | 已实现 |
| `fan run` | 字节码 `.凡码` | 虚拟机（VM）执行 | 规划中 |
| `fan build` | 源码 → 字节码 `.凡码` | 编译 | 规划中 |
| `fan build` | 源码 → 可执行文件（exe） | 编译 | 规划中 |
| `fan package` | 程序与依赖 → 可分发包 | 打包 | 规划中 |

约定：

- **fan-rust 全套实现**：同时具备树遍历与 VM 两条执行路径，并支持编译、打包，是唯一的目标形态。
- **其他宿主（含 `fan-go`）只做解释执行**：仅实现树遍历方式，不实现 VM 与编译；后续视情况再决定是否引入 VM。

## 三、待建设方向

- **字节码与 VM**：字节码格式 `.凡码`、VM 执行路径。
- **编译与打包**：编译产出字节码或可执行文件，以及程序打包工具。
- **模块管理工具**：凡语言的包管理与模块分发命令行工具。
- **模块服务**：模块的托管、检索与版本服务。

以上各项会在后续迭代中逐一建立，届时本页将补充对应的仓库与设计说明。
