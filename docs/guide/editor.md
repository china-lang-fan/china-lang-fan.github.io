# 编辑器与语言服务器

凡语言内置了一个语言服务器（Language Server），编辑器通过它获得实时诊断能力。命令为：

```sh
fan lsp
```

语言服务器通过标准输入输出（stdio）使用 [LSP](https://microsoft.github.io/language-server-protocol/) 协议与编辑器通信。

## VS Code

安装官方插件“凡语言支持”后，打开 `.凡` 或 `.fan` 文件即会自动在后台启动 `fan lsp`，无需额外配置。如果解释器不在 PATH 中，在设置 `fan.executablePath` 中指定路径即可。

可通过设置 `fan.languageServer.enable` 关闭语言服务器。

## 实时诊断

编辑器中会出现两类波浪线提示：

- **红色（错误）**：语法错误。
- **黄色（警告）**：语义上合法但很可能是笔误的写法。

目前的警告规则：

| 代码 | 含义 |
| --- | --- |
| `mixfix-space` | 分段函数调用的某两段之间出现了空格 |
| `mixfix-unresolved` | 按分段函数解析，但找不到名称与段数匹配的分段函数 |

## 两条词法原则

### 关键字前后必须有边界

关键字只有被空格、换行或符号边界分隔时才是关键字。与其他汉字或字母直接粘连时，整体被当作一个标识符：

```凡
变量 计数器 = 1
计数器加一
```

上例最后一行是对名为 `计数器加一` 的标识符求值，不会被理解成 `计数器 加 一`（变量、加号、数字）。`加`、`返回`、`如果` 等关键字必须用空格与两侧内容分开：

```凡
计数器 = 计数器 加 一
返回(计数器)
```

分段函数段名中包含 `的` 等字是允许的，例如 `修改用户(用户)的状态为(状态)`，因为 `的` 在那里是成员连接词而不是普通标识符的一部分。

### 分段函数段间不能有空格

分段函数调用各段必须紧邻：

```凡
修改(张三)的状态为无效
```

一旦段间出现空格，就变成两件不同的事——先执行开头的普通调用，再对返回值做成员访问：

```凡
修改(张三) 的状态为无效
```

这一行先普通调用 `修改(张三)`，然后读取其返回对象的 `状态为无效` 成员。编辑器会在空格处给出 `mixfix-space` 黄色告警，提示这里与分段函数调用不是一回事。

直接连接的多段函数同理：

```凡
从("北京")到("上海")乘坐("高铁")
```

`到` 或 `乘坐` 前一旦出现空格，就不再是整条分段函数调用。

## 其他编辑器

任何支持 LSP 的编辑器都可以用 `fan lsp` 接入。例如 Neovim（[nvim-lspconfig](https://github.com/neovim/nvim-lspconfig)）中可手动注册：

```lua
vim.lsp.config["fan"] = {
  cmd = { "fan", "lsp" },
  filetypes = { "fan" },
  root_markers = { ".git" },
}
vim.lsp.enable("fan")
```

其他编辑器（Emacs、Helix、Zed 等）在其 LSP 配置中将启动命令设为 `fan lsp`、语言 ID 设为 `fan` 即可。

语言服务器目前提供诊断；悬停、跳转定义、补全等能力会在后续版本陆续加入。
