# 错误处理

凡语言区分两类问题：

- **业务错误**：错误是普通值，函数通过多返回值返回 `值, 错误`。
- **运行时崩溃**：调用内建函数 `崩溃了(错误描述)` 展开调用栈，用 `稍后` 中的 `恢复()` 取回崩溃错误。

## 错误值

用 `错误("消息")` 创建错误，用 `.消息` 读取消息字符串：

```凡
变量 e = 错误("参数不合法")
打印(e)
打印(e.消息)
```

错误还可以携带**错误码**与**详情字典**，便于程序化分支和排错：

```凡
变量 e = 错误("余额不足", "PAY_001", {"金额": 10, "账户": "A01"})
打印(e.错误码)
打印(e.详情["金额"])
```

| 成员 | 含义 |
| --- | --- |
| `消息` | 错误消息字符串 |
| `错误码`（或 `码`） | 错误码字符串，没有时为空串 |
| `详情` | 结构化上下文字典，没有时为空字典 |
| `原因` | 被包装的原始错误，没有时为 `空` |
| `调用栈` | 产生错误处的调用栈，元素为含 `函数`/`文件`/`行`/`列` 的字典 |
| `追踪` | 包含消息、错误码、原因链与调用栈的完整文本 |

错误也可以作为类型标注：

```凡
变量 错误 e = 空
```

## 返回值、错误

函数返回 `值, 错误`，由调用方显式检查：

```凡
函数 除法(整数 a、整数 b) -> (整数，错误)
    如果 b 等于 0 那么
        返回 0、错误("除数不能为零")
    结束
    返回 a / b、空
结束

变量 商、e = 除法(10, 0)
如果 e 不等于 空 那么
    打印("出错：", e.消息)
否则
    打印("结果：", 商)
结束
```

## 检查：错误传播语法糖

`检查 调用` 等价于手动判断错误并提前返回：

```凡
函数 安全除法(整数 a、整数 b) -> (整数，错误)
    变量 结果 = 检查 除法(a, b)
    返回 结果、空
结束
```

规则：

- 调用成功时，`检查` 去掉最后的错误返回值。
- 调用失败时，当前函数立即返回该错误。
- 使用 `检查` 的函数，最后一个返回类型必须是 `错误`。
- `检查` 只处理普通错误值，不处理 `崩溃了` 触发的崩溃。
- 错误首次被 `检查` 传播时会自动记录调用栈，可通过 `e.调用栈` 或 `e.追踪` 查看。

> 注意：`检查` 与 `崩溃了` 是两条**互不相通**的错误轨道。`检查` 冒泡的是普通错误值，
> 只能靠每层函数签名里的 `错误` 返回位逐层向上传递；它**不能被 `稍后` 中的
> `恢复()` 接管**——`恢复()` 只消费 `崩溃了` 展开的崩溃。若当前函数末位返回类型不是
> `错误`，`检查` 错误会一路冒泡到顶层并以「未捕获的检查错误」终止程序。
> 需要就地兜底时，不要用 `检查`，改为显式判断多返回值里的错误位。

## 稍后：延迟调用

`稍后` 类似 Go 的 `defer`，用于注册函数退出时执行的调用。多个 `稍后` 按后进先出执行：

```凡
函数 处理()
    稍后 打印("第二")
    稍后 打印("第一")
结束

处理()
```

输出：

```text
第一
第二
```

`稍后` 的参数在注册时立即求值：

```凡
变量 名 = "旧"
稍后 打印(名)
名 = "新"
```

输出 `旧`。

也可以注册无参匿名函数：

```凡
函数 处理文件()
    稍后 函数()
        打印("关闭文件")
    结束
结束
```

即使函数中发生崩溃，已经注册的 `稍后` 也会执行。

## 崩溃了：触发运行时崩溃

`崩溃了(错误描述)` 是一个内建函数（不是语句关键字），类似 Go 的 `panic`。它接受
**一个字符串描述**，内部据此构造一个规范的错误对象（自动记录调用栈），并展开调用栈：

```凡
崩溃了("配置缺失")
崩溃了("权限不足，无法访问 " + 路径)
```

`崩溃了` 只接受错误描述，不能直接崩溃一个数字、字典或模型实例。需要结构化信息时，
先用 `错误(消息, 错误码, 详情)` 组装，再把它的消息交给 `崩溃了`；崩溃恢复后拿到的
始终是带 `.消息`、`.调用栈`、`.追踪` 等成员的规范错误对象。

## 恢复：在稍后中取回崩溃

`恢复()` 是一个无参内建函数，只能在 `稍后` 注册的函数中生效，类似 Go 的 `recover()`：

```凡
函数 安全执行()
    稍后 函数()
        变量 异常 = 恢复()
        如果 异常 不等于 空 那么
            打印行("已恢复：" + 异常.消息)
        结束
    结束

    崩溃了("测试")
结束

安全执行()
```

没有正在展开的崩溃时，`恢复()` 返回 `空`：

```凡
函数 普通函数()
    返回 恢复()
结束
```

`恢复()` 只会消费当前正在展开的崩溃值。如果不希望恢复，可以再次 `崩溃了`：

```凡
稍后 函数()
    变量 异常 = 恢复()
    打印行("记录日志")
    崩溃了(异常.消息)
结束
```

## 嵌套调用

崩溃会逐层展开调用栈，每层函数的 `稍后` 都会执行，直到某一层的 `稍后` 调用 `恢复()`：

```凡
函数 内层()
    崩溃了("深层失败")
结束

函数 外层()
    稍后 函数()
        变量 异常 = 恢复()
        打印行("外层恢复：" + 异常.消息)
    结束
    内层()
结束

外层()
```

始终没有被 `恢复()` 接管的崩溃会终止脚本，并报告「未恢复的崩溃」。

## 如何选择

- 用户输入错误、文件不存在、网络失败、解析失败：使用 `(值, 错误)`。
- 简化错误向上返回：使用 `检查`（仅当本函数也以 `错误` 收尾、愿意继续向上冒泡时）。
- 资源清理：使用 `稍后`。
- 程序状态损坏、不可继续执行：调用 `崩溃了(错误描述)`。
- 在边界恢复崩溃：在 `稍后` 中调用 `恢复()`（只能恢复崩溃，恢复不了 `检查` 错误）。

两条轨道的关键差异：`崩溃了` 触发的崩溃可在任意上层用 `稍后` + `恢复()` 接管；
`检查` 错误没有就地兜底语法，只能沿 `错误` 返回位传播，直到顶层。需要「试一次、
失败就地处理」时，用普通的多返回值判断而非 `检查`。
